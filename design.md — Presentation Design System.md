# design.md — Presentation Design System

Oct 18, 2026 · @영우

## 1. Overview

An Apple-inspired HTML presentation system for school and academic presentations on any subject. Decks are presenter-led: the speaker explains, the slide anchors. Slides carry keywords, evidence, equations, and visuals, not paragraphs.

The system has a **Core** that always applies and optional **Modules** that are used only when a deck needs them.

| Part | Contains | Use when |
| --- | --- | --- |
| Core | Layout, type, color, content rules, progress bar, general components | Always |
| Math module | KaTeX, function graphs, sliders | Equations or function plots appear |
| Data module | Bar and line charts on the `Graph` class | Numeric data is shown |
| Media module | Images and screenshots | A real image carries content |

Do not use a module the deck doesn't need. Decks without math may omit the KaTeX links entirely.

### Hard rules

These override anything else in this document.

1. Canvas is 1920×1080 px, scaled to fit. No `vw`/`vh` units inside slides.
2. Fonts: IBM Plex Sans KR / IBM Plex Sans for all text. KaTeX for math only.
3. Text inside slides is at least 28px, including text drawn on canvases. Exceptions: the progress bar (24px) and the navigation bar, which sits outside the slides.
4. No hex colors outside `:root`. HTML, CSS, and JS all use variables (JS reads them with `cssVar()`).
5. `--c-accent` is the only UI accent. It marks structure (title rule, timeline dots, TOC numbers, quote bar, progress fill), never individual items.
6. Orange (`--g-point`) appears only on canvases, only for special points.
7. No logos, decorative icons, gradients, or shadows. The only shadow in the system is on graph canvases.
8. Never shrink fonts to fit content. Split the slide or cut content.
9. All canvas drawing goes through the `Graph` class.
10. `slide.css` and `slide.js` match the reference code in sections 7 and 8. Only deck-specific graph functions are added.

## 2. Content

**One slide, one message.** Before writing a slide, state its point in one sentence. Anything that doesn't serve that point moves to another slide or gets cut. The point is carried by the content, not written as the title.

### Content budget (per standard slide)

- Title: a short noun phrase, 16 Korean characters or fewer.
- Bullets: 2–4 items, one line each. Noun phrases or short clauses, not complete sentences. No sub-bullets.
- Panels: at most one panel group per slide (see section 3).
- Display equations: at most 2.
- Graph slides: the graph plus at most one line of text.
- Over budget: split into two slides or cut. Never shrink fonts.

### Titles and wording

- Titles name the topic. Neutral and factual: no verbs, claims, questions, metaphors, or rhetorical phrasing.
  - Good: "문제 설정", "교점의 개수", "작품 개요", "제목의 반어"
  - Bad: "a가 커지면 두 교점이 사라진다", "한 번의 변형으로 W의 꼴이 된다"
- Subtitles are optional and only state scope or conditions (e.g. "a > 0").
- All slide text reads like lecture notes: plain and neutral. No rhetorical transitions ("이제", "드디어", "놀랍게도"), no exclamation marks, no question-form headings. This applies to cover and divider slides too.
- TOC section names: 8 Korean characters or fewer recommended. They also appear in the progress bar, where long names get cut off.

### Evidence over summary

- Slides show evidence: quotations, concrete scenes, numbers, dates, names. Interpretation and conclusions are spoken, not written.
- Never write a sentence that explains what the evidence means ("\~할수록 \~가 커짐", "\~를 드러냄", "\~의 효과").
- Every quotation carries its source and page number. If the page is unknown, leave `p. [ ]` for the presenter to fill.
- Do not state facts you are unsure of. Leave a marked blank (`[ ]`) instead.

### Presenter's view slide

A deck may include one slide for the presenter's own view (감상, 의견, 질문), placed after the content sections. This is the only slide where interpretation is written out. Never invent an opinion for the presenter: lay out the rows and leave `[직접 작성]` blanks.

### Media in content-heavy subjects

Decks about a book, person, place, or historical period should include at least one image slide (cover, photo, map) using the Media module. A deck made only of text slides has no visual rhythm.

## 3. Layout

Standard slides have no header. Each is a vertical flex column: `.title-zone` (auto height, 2px accent rule below) → `.content-zone` (fills the rest) → `.progress` (generated by slide.js). Horizontal margins are 90px on both sides.

### Alignment

- Default: content is top-aligned and left-aligned, starting right below the title. Display equations are left-aligned too (add `.txt-center` to center one deliberately).
- `.content-zone.center` only for slides with a single focal element (one quote, one equation) and for section dividers.
- Never center a bullet list horizontally.

### Leftover space

1. **Enlarge**: bigger graph or equation, or the `.lg` variant on `.facts` / `.rows`.
2. **Anchor**: if the slide has a main block plus a closing element (a panel, a short bullet list, a caption), use `.content-zone.split` so the closing element sits on the bottom margin.
3. **Add** a supporting element only if it carries new information.
4. Otherwise leave the space. Never stretch blocks to fill height: empty space inside a block reads worse than empty space on the slide.

### Containers

- Default: content sits on the slide background, separated by hairlines (`--c-border`) and whitespace.
- Use a `.panel` (plain white, no colored border) only when two or three blocks are compared side by side, or when one element differs in kind from the rest of the slide (a quotation used as evidence, a definition).
- At most one panel group per slide. Never a grid of four or more panels.
- Never highlight one item in a list with color. Order and position carry importance.
- Emphasized text inside the content zone (values, amounts, terms) tops out at 44px so it never competes with the 62px title. Only `.stat-num` on a dedicated number slide goes larger.

### Progress bar

- Generated from the TOC slide's `.toc-text` entries. Mark each slide with `data-section="N"` (1-based TOC index), or `data-section="end"` on the references slide.
- Shown on standard slides and the references slide. Not on cover, TOC, section dividers, or outro (they have no `data-section`).
- One segment per section across the width. Past sections are filled; the current segment fills in proportion to the slide's position within its section; references fill everything.
- Each section name sits under its own segment. The current one is bold.
- 7 sections or fewer: every name is shown.
- 8 or more: names one step from the current section are muted, two steps away are faint (`--c-faint`), and farther segments have no name.
- The page number sits at the right end. Text is 24px.
- The references slide is not a section and never appears in the TOC.

### Navigation bar

Top-right, outside the slides, opacity 0.2 at rest and 0.5 on hover. Keys: → ↓ PageDown Space for next, ← ↑ PageUp for previous. Keys are ignored while a slider or input has focus.

## 4. Color and typography

All colors are CSS variables defined once in `:root` (full list in section 7).

| Context | Variable |
| --- | --- |
| Slide background | `--c-bg` |
| Panels, graph backgrounds | `--c-white` |
| Cover, outro, section divider | `--c-dark` |
| Body text | `--c-ink` / `--c-on-dark` |
| Secondary text, labels, captions | `--c-muted` / `--c-on-dark-muted` |
| Far progress-bar labels | `--c-faint` |
| Structure (title rule, dots, TOC numbers, quote bar, progress fill) | `--c-accent` / `--c-accent-dk` on dark |
| Negative / positive meaning only | `--c-red` / `--c-green` |
| Hairlines | `--c-border` |
| Graph curves in order | `--g-curve-1` → `-2` → `-3` |
| Special points on graphs | `--g-point` |

Weight ladder: 700 cover title and outro main only · 600 titles, labels, emphasis · 400 body and math · 300 cover and outro subtitles only. Headlines use negative tracking (-0.02em titles, -0.03em cover and outro).

### Core components

| Component | Use for | Markup |
| --- | --- | --- |
| `.facts` (`.lg`) | 2–8 label/value pairs in two columns | `.fact` > `.fact-key` + `.fact-val` |
| `.rows` (`.lg`) | Parallel items with a description (characters, terms, features) | `.row` > `.row-term` + `.row-desc` (optional `.src` inside for a source line) |
| `.timeline` | 3–5 ordered events | `.tl-item` (`.key` for the turning point) > `.tl-label` + `.tl-title` + `.tl-body` |
| `.contrast` | Two-way comparison | two `.panel` children, each `.c-head` + `.c-item` (`.c-big` + `.c-desc`) |
| `.panel` | Set-apart element (quote as evidence, definition) | optional `.panel-title` first |
| `.quote` (`.sm`) | Quoted passage | followed by `.quote-src` |
| `.bullet-list` (`.sm`) | 2–4 short points | `<ul><li>` |
| `.data-table` | Comparison or classification table | `<table>` with `<thead>`; `<strong>` for an emphasized cell |
| `.stat-row` | 1–3 headline numbers on a dedicated slide | `.stat` > `.stat-num` + `.stat-label` |
| `.ref-list` | References | `<ol><li>` with hanging indent |
| `.cols` | Side-by-side layout | `.col`, `.col-4` (40%), `.col-5` (50%), `.col-6` (55%) |

Text helpers: `.txt-sm` `.txt-lg` `.txt-muted` `.txt-accent` `.txt-red` `.txt-green` `.txt-bold` `.txt-center`. Item counts may be uneven when the content is uneven; do not pad a list to match another.

## 6. Modules

### Math module

- Inline math `\( … \)`, display math `\[ … \]` inside `.display-math` (44px) or `.display-math-sm` (38px). Left-aligned by default.
- Definitions and theorems go in a `.panel` with a `.panel-title` (정의, 정리, 결과).
- Function graphs use the `Graph` class. Curves in order `--g-curve-1`, `-2`, `-3`; reference lines (y = x, asymptotes) with `drawDash` in `--g-ref`; special points with `dot(x, y, cssVar('--g-point'))`.
- Register every draw function in `drawAllGraphs()`. Interactive graphs create a new `Graph` and redraw on every input event.

Interactive graph layout (canvas left, controls right):

```html
<div class="content-zone">
  <div class="cols">
    <div class="graph-wrap"><canvas id="g-main" width="1040" height="650"></canvas></div>
    <div class="col controls">
      <div class="legend vertical">
        <div class="legend-item"><div class="legend-line c1"></div><span>\(y = a^x\)</span></div>
        <div class="legend-item"><div class="legend-dash"></div><span>\(y = x\)</span></div>
        <div class="legend-item"><div class="legend-dot"></div><span>교점</span></div>
      </div>
      <div class="slider-row">
        <span class="slider-label">\(a\)</span>
        <input type="range" id="a-slider" min="0.3" max="2" step="0.001" value="1.2">
        <span class="slider-value" id="a-value">1.200</span>
      </div>
      <div class="preset-row"><button class="preset-btn" data-a="0.5">\(a = 0.5\)</button></div>
      <div class="info-line" id="a-info"></div>
    </div>
  </div>
</div>
```

The canvas `width`/`height` attributes are its logical size in slide pixels; the class handles high-DPI rendering.

### Data module

The same `Graph` class with `bars`, `series`, and `labelsX` (section 8). Categories sit at x = 1 … n; use `xMin: 0.4, xMax: n + 0.6`. One chart per slide, at most 3 series, axis unit labeled once, no 3D, no pie charts.

### Media module

```html
<figure class="media" style="height: 640px;">
  <img src="images/cover.jpg" alt="설명">
  <figcaption>출처 또는 설명</figcaption>
</figure>
```

- Images must carry content (a cover, a scene, a place, a screenshot being discussed). No decorative stock photos.
- Give the figure an explicit height. Crop screenshots instead of shrinking them.
- Every non-original image gets a source caption.

const stage = document.getElementById('stage');

const SECTIONS = [...document.querySelectorAll('.toc-item .toc-text')]

class Graph {
  constructor(id, { xMin, xMax, yMin, yMax }) {
    const c = this.canvas = document.getElementById(id);
    if (!c) return;
    if (!c.dataset.w) { c.dataset.w = c.width; c.dataset.h = c.height; }
    this.W = +c.dataset.w; this.H = +c.dataset.h;
    const r = Math.max(2, window.devicePixelRatio || 1);
    if (c.width !== this.W * r) {
      c.width = this.W * r; c.height = this.H * r;
      c.style.width = this.W + 'px'; c.style.height = this.H + 'px';
    }
    this.ctx = c.getContext('2d');
    this.ctx.setTransform(r, 0, 0, r, 0, 0);
    Object.assign(this, { xMin, xMax, yMin, yMax });
  }
  wx(x) { return (x - this.xMin) / (this.xMax - this.xMin) * this.W; }
  wy(y) { return (this.yMax - y) / (this.yMax - this.yMin) * this.H; }

  clear() {
    this.ctx.fillStyle = cssVar('--g-bg');
    this.ctx.fillRect(0, 0, this.W, this.H);
  }
  drawGrid(stepX = 1, stepY = 1) {
    const { ctx, W, H } = this;
    ctx.beginPath(); ctx.strokeStyle = cssVar('--g-grid'); ctx.lineWidth = 1;
    for (let x = Math.ceil(this.xMin / stepX) * stepX; x <= this.xMax; x += stepX) {
      ctx.moveTo(this.wx(x), 0); ctx.lineTo(this.wx(x), H);
    }
    for (let y = Math.ceil(this.yMin / stepY) * stepY; y <= this.yMax; y += stepY) {
      ctx.moveTo(0, this.wy(y)); ctx.lineTo(W, this.wy(y));
    }
    ctx.stroke();
  }
  drawAxes() {
    const { ctx, W, H } = this;
    ctx.beginPath(); ctx.strokeStyle = cssVar('--g-axis'); ctx.lineWidth = 1.5;
    if (this.yMin <= 0 && this.yMax >= 0) { ctx.moveTo(0, this.wy(0)); ctx.lineTo(W, this.wy(0)); }
    if (this.xMin <= 0 && this.xMax >= 0) { ctx.moveTo(this.wx(0), 0); ctx.lineTo(this.wx(0), H); }
    ctx.stroke();
  }
  drawCurve(f, color, lw = 3, steps = 800) {
    const { ctx } = this;
    ctx.beginPath(); ctx.strokeStyle = color; ctx.lineWidth = lw;
    let pen = false;
    for (let i = 0; i <= steps; i++) {
      const x = this.xMin + (this.xMax - this.xMin) * i / steps;
      const y = f(x);
      const ok = isFinite(y) && y >= this.yMin - 1 && y <= this.yMax + 1;
      if (!ok) { pen = false; continue; }
      pen ? ctx.lineTo(this.wx(x), this.wy(y)) : (ctx.moveTo(this.wx(x), this.wy(y)), pen = true);
    }
    ctx.stroke();
  }
  drawDash(f, color = cssVar('--g-ref'), lw = 3) {
    this.ctx.setLineDash([12, 8]); this.drawCurve(f, color, lw); this.ctx.setLineDash([]);
  }
  dot(x, y, color, r = 9) {
    const { ctx } = this;
    ctx.beginPath(); ctx.arc(this.wx(x), this.wy(y), r, 0, Math.PI * 2);
    ctx.fillStyle = color; ctx.fill();
    ctx.strokeStyle = cssVar('--c-white'); ctx.lineWidth = 3; ctx.stroke();
  }
  text(x, y, str, color = cssVar('--c-ink'), dx = 12, dy = -12, size = 28) {
    const { ctx } = this;
    ctx.fillStyle = color; ctx.textAlign = 'left';
    ctx.font = `${size}px "IBM Plex Sans KR","IBM Plex Sans",sans-serif`;
    ctx.fillText(str, this.wx(x) + dx, this.wy(y) + dy);
  }
  ticksX(vals, fmt = String, dy = 34, size = 28) {
    const { ctx } = this;
    const y0 = Math.min(Math.max(this.wy(0), 0), this.H - dy - 4);
    ctx.fillStyle = cssVar('--g-tick'); ctx.textAlign = 'center';
    ctx.font = `${size}px "IBM Plex Sans",sans-serif`;
    for (const v of vals) ctx.fillText(fmt(v), this.wx(v), y0 + dy);
  }
  ticksY(vals, fmt = String, dx = -12, size = 28) {
    const { ctx } = this;
    const x0 = Math.min(Math.max(this.wx(0), -dx + 44), this.W);
    ctx.fillStyle = cssVar('--g-tick'); ctx.textAlign = 'right';
    ctx.font = `${size}px "IBM Plex Sans",sans-serif`;
    for (const v of vals) ctx.fillText(fmt(v), x0 + dx, this.wy(v) + 10);
  }

  /* Data module: categories at x = 1..n */
  bars(values, color = cssVar('--g-curve-1'), w = 0.6) {
    const { ctx } = this;
    ctx.fillStyle = color;
    values.forEach((v, i) => {
      const x0 = this.wx(i + 1 - w / 2), x1 = this.wx(i + 1 + w / 2);
      const y0 = this.wy(0), y1 = this.wy(v);
      ctx.fillRect(x0, Math.min(y0, y1), x1 - x0, Math.abs(y1 - y0));
    });
  }
  series(values, color = cssVar('--g-curve-1'), lw = 3) {
    const { ctx } = this;
    ctx.beginPath(); ctx.strokeStyle = color; ctx.lineWidth = lw;
    values.forEach((v, i) => i ? ctx.lineTo(this.wx(i + 1), this.wy(v))
                               : ctx.moveTo(this.wx(i + 1), this.wy(v)));
    ctx.stroke();
    values.forEach((v, i) => this.dot(i + 1, v, color, 7));
  }
  labelsX(labels, dy = 38, size = 28) {
    const { ctx } = this;
    ctx.fillStyle = cssVar('--c-muted'); ctx.textAlign = 'center';
    ctx.font = `${size}px "IBM Plex Sans KR","IBM Plex Sans",sans-serif`;
    labels.forEach((t, i) => ctx.fillText(t, this.wx(i + 1), this.wy(0) + dy));
  }
}

## 9. Final check before output

1. Every slide's point fits in one sentence; the title is a neutral noun phrase of 16 characters or fewer.
2. Every slide is within the content budget. No sentence explains what the evidence means (except on the presenter's view slide).
3. Every quotation has a source and a page number or `p. [ ]`. Uncertain facts are left as `[ ]` blanks.
4. Content is top- and left-aligned unless the slide has a single focal element. No bullet list is centered.
5. Leftover space was handled by enlarging or anchoring, never by stretching blocks or adding repeated content.
6. Panels appear only for side-by-side comparison or one set-apart element; at most one panel group per slide. No list item is highlighted with color.
7. No emphasized text inside the content zone exceeds 44px (except `.stat-num`).
8. No text below 28px inside slides except the progress bar.
9. No hex colors outside `:root`; no inline color styles.
10. Every content slide and the references slide carries the correct `data-section`; cover, TOC, dividers, and outro carry none. References are not in the TOC.
11. Slide order: cover first, outro last, references right before the outro, no two dark slides adjacent.
12. Decks about a book, person, place, or period include at least one image slide.
13. slide.css and the core of slide.js match sections 7 and 8; only `drawAllGraphs()` and deck-specific functions were added.
